《战争雷霆》的辅助工具。它从游戏自带的本地服务器（`http://127.0.0.1:8111`）读取击杀信息，
显示当前谁在使用什么载具，并在本地积累战斗与玩家的历史记录。

> 本项目与 Gaijin Entertainment 无关，也未获得其认可。War Thunder 是 Gaijin Entertainment
> 的商标，此处仅用于说明兼容性。本程序只与游戏自身提供的本地接口通信，不修改任何游戏文件。

## 这样做被允许吗？

`127.0.0.1:8111` 是《战争雷霆》自己启动的官方本地接口，直播插件、WTRTI 等工具都在使用它。
`/hudmsg` 返回的正是屏幕上已经显示的击杀信息。其中不包含任何隐藏数据：没有未被发现的敌人位置，
也没有他们载具的状态。本程序只是替你记住你本来就能看到的内容。

**决定一切的限制：** 游戏不会对外提供完整记分板。只有在击杀他人、造成伤害或被击杀之后，
玩家才会出现在表格中。开战几分钟后通常能覆盖大部分玩家，但永远不会立即覆盖全部。

## 一个窗口，八个标签页

- **战斗** — 实时表格：左侧队友，右侧敌人。每种载具都带有类别图标
  （`▮` 地面载具，`◬` 防空，`✈` 飞机，`⊹` 直升机）。你自己的一行会高亮显示。
- **统计** — 四块计数器（自启动以来、今天、本周、本月，每块可单独重置），下方是图表：
  按小时的战斗分布、连胜与连败、按天的 KDA 与胜率（七日滑动平均）、半年活跃度日历。
- **战斗记录** — 历史列表，可按昵称或载具搜索，并按时间段、胜负与自己的载具筛选。
  列表上方的汇总只统计筛选结果，而非整个数据库。点击某场战斗可展开完整名单，含奖励与载具。
- **玩家** — 指定时间段内的队友榜与对手榜，可设置「最少遭遇次数」。
- **我的载具** — 胜率与每种载具的统计，旁边是敌方最常使用的载具。所有列均可排序。
- **使用说明** — 用平实语言和较大字号写的指南。标题栏的「?」按钮会直接打开与当前标签页对应的章节。
- **关于** — 版本、许可证、数据文件位置。
- **设置** — 托盘与自动启动、昵称、界面语言（英文、俄文、中文）、界面大小、窗口置顶、数据库大小以及危险操作。

计数器并不存储数字：数据库中保存的是上次重置的时刻，数量由查询得出。
因此重置计数器不会删除任何内容，而清空历史会自动把计数器归零。

## 程序如何解读一场战斗

**战斗边界。** `/hudmsg` 中的消息编号贯穿整个游戏会话，新战斗开始时不会重置，
而日志本身是一个同时覆盖多场战斗的滑动窗口。唯一可靠的边界是 `time` 字段，
即从战斗开始起算的秒数：进入新战斗时它会回落。程序还考虑到重生界面同样返回
`valid: false`（与机库相同），因此短暂中断不会被当作新战斗。

**队伍。** 接口中没有队伍标识。阵营通过图推导：每次击杀或伤害都意味着「这两人处于对立阵营」，
着色由此扩散。有两个锚点把这张图与*你的*阵营关联起来：你出现在击杀信息中，
以及来自 `/gamechat` 的队伍频道消息——该频道只有己方能看到。
尚未与你的阵营建立联系的玩家会分组显示：组内已知谁与谁对立，只是不知道哪一半是你的。

**被过滤掉的内容。** 侦察无人机、导弹及其他游戏实体（`[ии] Recon Micro`、
`weapons/us_agm_88a/short`、`130mm_9m120_1`）不是玩家：击落它们既不算死亡也不算击杀。

## 数据库

通过 Node 内置的 `node:sqlite` 模块使用 SQLite —— **没有原生依赖**，
无需编译，也无需针对 Electron ABI 重新构建。文件位置：`%APPDATA%/Sightline/battles.db`。

程序不会自动删除任何数据。基于实际结构的实测（每场战斗 32 名玩家，含出击、对决与奖励）：

| 战斗场数 | 大小 |
|---|---|
| 1 000 | 13 MB |
| 10 000 | 126 MB |
| 50 000 | 632 MB |

每次危险操作之前都会在数据库旁生成备份，并且需要输入确认词，误点不会造成损失。

## 从这里开始

1. 在设置中填写**你的游戏昵称**。没有它，程序无法区分队友与敌人。
   不需要写战队标签：`Username` 也能匹配 `[CLAN] Username`。
2. 「窗口置顶」在游戏以**无边框窗口**模式运行时有效；Windows 不会把它显示在独占全屏之上。
3. 表格在新战斗开始时清空，而不是在你阵亡或返回机库时。

## 战斗表格中的内容

| 列 | 含义 |
|---|---|
| K / D / A | 击杀、损失与助攻。助攻是推导出来的，而非游戏提供：你击伤了目标，由他人完成击杀 |
| ★ | 本场战斗获得的奖励——悬停查看列表。仅包含游戏写入击杀信息的奖励 |
| 状态 | `在战斗中` · `已被击毁 · 选择载具中` · `已离开` · `未出击` |
| 载具 | 每次出击一个标签，按顺序排列。`×N` 表示该载具的击杀数，划掉的标签表示载具被击毁，实线边框为当前载具，虚线表示该次出击结束但未确认死亡 |

最后击杀你的人会以金色边框标出——这是「以眼还眼」奖励的目标。当该奖励无法再获得时，边框会自动消失。

## 如何确认统计数据是真实的

统计数据是由运行在玩家自己电脑上的程序收集的——这意味着它原则上可以被伪造。我们不回避这一点，
也不打算用代码混淆来掩盖：客户端用来签名请求的任何密钥，都存放在我们要防范的那个人的机器上。

我们的做法是让战斗记录彼此印证。同一场战斗中可能有多名玩家在使用本程序，他们看到的是同一份击杀信息。
当他们对同一事件的记录一致时，该场战斗会被标记为**绿色对勾**。如果某人的数据与其他人相互矛盾，
这一分歧会永久保留在数据库中。

关键在于**由谁确认**。队友是可以自己带来的：用第二个账号组队，就能给自己确认任何内容。
但对手不是自己挑选的——你无法让自己的小号出现在敌方阵营。因此来自敌方的确认价值高得多，
绿色对勾正是为此而设。

没有对勾并不等于指控。在用户还不多的阶段，玩家在大多数战斗中都会是唯一的使用者，根本无人可供印证。
这类战斗保持中性。账号上的黄色三角并非因为缺少见证者，而只会因为与他人记录存在**已确认的分歧**——
而且不是一次分歧就会出现，需要形成稳定的模式：客户端可能是在战斗中途启动的，或者丢失了部分记录，
那是数据缺口，而不是欺骗。

使用本程序的人越多，见证网络就越密集，伪造数据也就越没有意义。反过来也一样：初期经过验证的数据会很少，
因此我们会如实显示个人资料中有多少场战斗已获确认。

## 无法实现的功能

- **战斗奖励与经验值。** 本地接口完全不提供战后结算界面的数据。
  只有通过屏幕识别才能获取——那是另一个独立项目。
- **地图名称与战斗等级。** 接口中同样没有。
- **完整的玩家列表。** 参见上文的限制说明。

## 项目结构

| 文件 | 用途 |
|---|---|
| `src/main/wt-client.js` | 轮询 `/hudmsg`、`/map_info.json`、`/gamechat`；判定战斗边界 |
| `src/main/killfeed-parser.js` | 击杀信息 → 参与者、事件类型、奖励 |
| `src/main/verbs.js` | 动词与奖励的表述（俄语/英语）——需要扩展时只改这里 |
| `src/main/battle-state.js` | K/D/A、出击、状态、队伍图（带奇偶性的并查集） |
| `src/main/vehicle-class.js` | 用于图标的载具类别；过滤游戏实体 |
| `src/main/db.js` | SQLite：战斗、玩家、计数器、奖励、备份 |
| `src/main/migrations.js` | 架构版本存于 `PRAGMA user_version`；各步骤按顺序执行，且只执行一次 |
| `src/renderer/` | 单一窗口：标签页、队友与敌人分栏 |
| `src/renderer/charts.js` | 内联 SVG 图表，不使用第三方库 |
| `src/i18n/` | 三种语言的界面文本；键集一致性由测试保证 |
| `src/renderer/i18n.js` | t(key)、复数形式、写入标记 |

让程序走到今天的最初计划：[docs/PLAN.md](docs/PLAN.md)。后续计划在 issues 中讨论。

`npm run harness` 会把整个界面连同占位数据打包成单个 HTML 文件：无需启动 Electron，
即可在浏览器中查看和调整版式。

## 扩展解析器

如果设置中出现「未识别的击杀信息」区块，请复制该行并把它的表述加入 `src/main/verbs.js`。
其他地方无需修改。

一个值得注意的陷阱：JavaScript 中的 `\b` 基于 ASCII 单词字符，
因此在西里尔字母旁边永远不会匹配。俄语表述的正则不能使用它。
