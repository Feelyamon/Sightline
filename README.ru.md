# Sightline

[🇬🇧 English](README.md) · 🇷🇺 Русский · [🇨🇳 中文](README.zh.md)

Companion-приложение для War Thunder. Читает кил-фид из локального веб-сервера самой игры
(`http://127.0.0.1:8111`), показывает, кто на какой технике воюет прямо сейчас, и копит локальную
историю боёв и игроков.

> Проект не аффилирован с Gaijin Entertainment и не одобрен ею. War Thunder — товарный знак Gaijin
> Entertainment; название используется здесь только для указания совместимости. Приложение работает
> исключительно с локальным API, который игра предоставляет сама, и ничего в клиенте не меняет.

## Это законно?

`127.0.0.1:8111` — официальный локальный API, который War Thunder поднимает сам; на нём работают
стримерские оверлеи, WTRTI и подобные инструменты. Эндпоинт `/hudmsg` отдаёт ровно тот кил-фид,
который уже нарисован у тебя на экране. Скрытых данных там нет: ни позиций незасвеченных врагов, ни
состояния их машин. Приложение просто запоминает за тебя то, что ты и так читаешь глазами.

**Ограничение, которое определяет всё остальное:** полного скорборда игра наружу не отдаёт. Игрок
попадает в таблицу только после того, как кого-то убил, кого-то повредил или был убит. На практике
через пару минут боя это большая часть лобби, но никогда не все и не мгновенно.

## Запуск

```bash
npm install
```

```bash
npm start
```

## Одно окно, восемь вкладок

- **Бой** — живая таблица: слева свои, справа противники. У каждой машины иконка класса
  (`▮` наземка, `◬` ЗСУ, `✈` самолёт, `⊹` вертолёт). Своя строка подсвечена.
- **Статистика** — четыре плитки счётчиков (с запуска, сегодня, неделя, месяц; каждая
  сбрасывается отдельно), под ними графики: бои по часам суток, серии побед и поражений,
  КДА и винрейт по дням скользящим средним за неделю, календарь активности за полгода.
- **Бои** — история с поиском по нику или технике и фильтрами по периоду, исходу и своей
  машине. Сводка над списком считается по отфильтрованной выборке, а не по всей базе.
  Клик по бою раскрывает полный состав с наградами и техникой.
- **Игроки** — топ союзников и топ противников за период с порогом «минимум встреч».
- **Моя техника** — винрейт и статистика по каждой машине рядом с тем, что чаще всего выкатывают
  против. Все столбцы сортируются.
- **Инструкция** — как всё работает, простым языком и крупным шрифтом. Кнопка «?» в шапке
  открывает раздел про ту вкладку, на которой вы сейчас стоите.
- **О программе** — версия, лицензия, где лежит файл данных.
- **Настройки** — трей и автозапуск, ник, язык интерфейса (русский, английский, китайский), размер интерфейса,
  окно поверх других, размер базы и опасные операции.

Счётчики не хранят числа: в базе лежит момент последнего сброса, а количество считается запросом.
Поэтому сброс счётчика ничего не удаляет, а очистка истории обнуляет счётчики сама.

## Как читается бой

**Границы боёв.** Номера сообщений в `/hudmsg` сквозные через всю сессию игры и в новом бою не
обнуляются, а сам журнал — скользящее окно сразу на несколько боёв. Единственный надёжный признак
границы — поле `time`, секунды с начала боя: на стыке оно падает. Учтено, что экран респавна тоже
отдаёт `valid: false`, ровно как ангар, поэтому короткий перерыв новым боем не считается.

**Команды.** Признака команды в API нет. Стороны выводятся графом: каждое убийство или повреждение
означает «эти двое по разные стороны», и раскраска расходится дальше. Привязывают граф к *твоей*
стороне два якоря: твоё появление в фиде и командный чат из `/gamechat`, который виден только своей
команде. Игроки, ещё не связанные с твоей стороной, показываются группами: внутри группы известно,
кто кому противостоит, неизвестно лишь, какая половина твоя.

**Что отсеивается.** Разведдроны, ракеты и прочие игровые сущности (`[ии] Recon Micro`,
`weapons/us_agm_88a/short`, `130mm_9m120_1`) не игроки: их уничтожение не смерть и не фраг.

## База данных

SQLite через встроенный в Node модуль `node:sqlite` — **нативных зависимостей нет**, ничего не
компилируется и не пересобирается под ABI Electron. Файл: `%APPDATA%/Sightline/battles.db`.

Автоматически ничего не удаляется. Замер на настоящей схеме (32 игрока в бою со всеми вылетами,
дуэлями и наградами):

| Боёв | Размер |
|---|---|
| 1 000 | 13 МБ |
| 10 000 | 126 МБ |
| 50 000 | 632 МБ |

Перед любой разрушительной операцией рядом с базой создаётся копия, а само действие требует ввести
слово подтверждения — случайный клик ничего не стоит.

## С чего начать

1. Впиши **свой игровой ник** в настройках. Без него приложение не отличит своих от врагов.
   Клан-тег не нужен: `Username` найдётся и в строке `[CLAN] Username`.
2. «Поверх всех окон» работает, если игра запущена в режиме **оконный без рамки**; поверх
   эксклюзивного полноэкранного режима Windows окно не покажет.
3. Таблица очищается на старте нового боя, а не когда ты погиб или вышел в ангар.

## Что показывает таблица боя

| Колонка | Смысл |
|---|---|
| K / D / A | фраги, потери и ассисты. Ассисты выводятся, а не берутся из игры: ты повредил цель, добил её другой |
| ★ | награды за бой — список по наведению. Только те, что игра пишет в кил-фид |
| Статус | `в бою` · `уничтожен · выбирает` · `вышел` · `не выехал` |
| Техника | чип на каждый вылет по порядку. `×N` — фраги на этой машине, зачёркнутый чип — машину потеряли, сплошная рамка — текущая, пунктир — вылет закончился без подтверждённой гибели |

Тот, кто убил тебя последним, обведён золотом — это цель для «Око за око». Обводка пропадает, когда
награду уже не получить.

## Откуда известно, что статистика настоящая

Статистику собирает программа на компьютере игрока — значит, её в принципе можно подделать.
Мы не делаем вид, что это не так, и не пытаемся спрятать проблему за обфускацией: любой ключ,
которым клиент подписывает запрос, лежит на машине того, от кого мы защищаемся.

Вместо этого бои проверяются друг о друга. В одном бою может оказаться несколько игроков
с этой программой, и все они видят один и тот же кил-фид. Если их записи об одном событии
сходятся — бой помечается **зелёной галочкой**. Если чьи-то данные противоречат остальным,
расхождение остаётся в базе навсегда.

Ключевая деталь — **кто именно подтвердил**. Союзника можно привести с собой: взять второй
аккаунт в отряд и подтвердить самому себе что угодно. А вот противников не выбирают —
попасть своим вторым аккаунтом против себя нельзя. Поэтому подтверждение со стороны
противника весит несравнимо больше, и зелёная галочка ставится именно за него.

Отсутствие галочки — не обвинение. Пока пользователей мало, в большинстве боёв игрок будет
единственным, и подтверждать его записи просто некому. Такие бои остаются нейтральными.
Жёлтый треугольник у аккаунта появляется не за нехватку свидетелей, а только за
**подтверждённые расхождения** с чужими записями — и не за одно, а за устойчивую картину:
клиент мог запуститься посреди боя или потерять часть строк, и это не обман, а пробел.

Чем больше людей пользуется программой, тем плотнее сеть свидетелей и тем меньше смысла
что-либо подделывать. Это же работает и в обратную сторону: проверенных данных с самого
начала будет немного, и мы честно показываем, сколько боёв в профиле подтверждено.

## Чего не будет

- **Награды и опыт за бой.** Экран результатов локальный API не отдаёт вообще. Достать это можно
  только распознаванием экрана — отдельный проект.
- **Название карты и боевой рейтинг.** Их в API тоже нет.
- **Полный список игроков.** См. ограничение выше.

## Структура

| Файл | Назначение |
|---|---|
| `src/main/wt-client.js` | опрос `/hudmsg`, `/map_info.json`, `/gamechat`; границы боёв |
| `src/main/killfeed-parser.js` | строка фида → участники, тип события, награды |
| `src/main/verbs.js` | формулировки глаголов и наград (ru/en) — единственное место для доработки |
| `src/main/battle-state.js` | K/D/A, вылеты, статусы, граф команд (union-find с чётностью) |
| `src/main/vehicle-class.js` | класс техники для иконок; отсев игровых сущностей |
| `src/main/db.js` | SQLite: бои, игроки, счётчики, награды, резервные копии |
| `src/main/migrations.js` | версия схемы в `PRAGMA user_version`, шаги по порядку и по одному разу |
| `src/renderer/` | одно окно: вкладки, разделение своих и врагов |
| `src/renderer/charts.js` | графики инлайновым SVG, без сторонних библиотек |
| `src/i18n/` | строки интерфейса на трёх языках; ключи одинаковые, проверяются тестом |
| `src/renderer/i18n.js` | t(key), склонение по числу, подстановка в разметку |

Планы по этапам — [ROADMAP.txt](ROADMAP.txt). Исходный план, по которому приложение
дошло до текущего состояния, — [docs/PLAN.md](docs/PLAN.md).

`npm run harness` собирает весь интерфейс в один HTML-файл с данными-заглушкой: вёрстку
удобно смотреть и править в браузере, не запуская Electron.

## Доработка парсера

Если в настройках появился блок «Нераспознанные строки кил-фида» — скопируй строку и добавь её
формулировку в `src/main/verbs.js`. Больше нигде править не нужно.

Одна ловушка, о которой стоит знать: в JavaScript `\b` опирается на латиницу и рядом с кириллицей
не срабатывает никогда. В шаблонах для русских формулировок его использовать нельзя.
